# 人员管理

人员页使用 MySQL `persons` 表。工资页仍为独立演示数据，不与人员页同步。

## 加密配置

在 `.env.development.local` 配置 `PERSONNEL_ENCRYPTION_KEY`，内容为32字节随机数据的标准 Base64 字符串。生产环境由部署平台注入同名变量，禁止使用 `NEXT_PUBLIC_` 前缀或将真实密钥提交到 Git。

可用 Node.js 的 `crypto.randomBytes(32).toString('base64')` 生成密钥。密钥必须持久保存并与数据库分别备份；修改或丢失密钥会导致现有敏感资料无法读取。本版本不提供密钥轮换，不接受历史明文作为加密内容。

身份证、工资卡号、电话在数据库中整体加密；接口和导出文件提供原始文本。当前没有新增身份认证，部署应沿用受控访问环境。不要记录接口正文或将导出文件放在公共目录。

## 花名册

使用 `.xlsx`，工作表名为“花名册”。第1行为“农民工花名册”，第2行为编制单位、月份，第3行为固定13列表头，第4行起为人员。

列顺序：序号、姓名、性别、民族、籍贯、身份证号码、工资卡号、开户行、工种、上场时间、撤场时间、联系电话、备注。

只保存姓名、性别、民族、籍贯、身份证号码、工资卡号、开户行、联系电话。导出工种统一填写“砌砖”，上场时间、撤场时间、备注留空。编制单位和月份在导出时填写，不写入人员表。

文件最多5 MB、5000行，解压总量最多25 MB。不支持公式和加密工作簿。身份证、卡号、电话应为文本；已经被 Excel 转成不精确数字的号码必须从原始资料重新填写，系统不会猜测修复。

文件内或数据库存在重复姓名、任一行无效时整批拒绝；成功导入全部新增，不覆盖旧资料。导出当前搜索结果全部行，不受分页限制；模板下载不访问数据库。

## 接口

- `GET /api/personnel?query=&page=1&pageSize=10`：返回 `items、page、pages、total、totalPeople`，页容量支持5、10、20。
- `POST /api/personnel`：八个人员字符串字段，返回服务端生成的字符串 `id`。
- `PUT /api/personnel/[id]`：完整更新八个字段。
- `DELETE /api/personnel`：JSON `{ ids: string[] }`，关联工资记录或部分ID不存在时整批拒绝。
- `POST /api/personnel/import`：请求体为原始xlsx文件，返回 `{ count }`。
- `GET /api/personnel/export?query=&unit=&month=2026-09`：下载文件；增加 `template=1` 下载空模板。

错误返回中文 `message`，导入行错误附 `issues: { row, field, message }[]`；校验错误400、记录不存在404、冲突409、大小超限413、密钥配置或解密错误503。所有响应禁止HTTP缓存。

列表在服务端解密后进行搜索，仅将当前页发送给客户端，适合几百至几千人的规模。规模显著增长后需要单独设计检索策略。
